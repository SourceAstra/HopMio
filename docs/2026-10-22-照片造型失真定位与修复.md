# 照片造型失真定位与修复

## 1. 问题如何产生

作品 `37e7bfb7-eaf7-4388-94c4-6cb563f35192`（还原图片）的几何方案把三片叶面定义为 `ellipsoid`，却命名为“涡轮流线叶片”。执行器 `blender/tools.py::primitive` 按 shape 创建球体并按尺寸变换，名称不会产生弯曲或扭转。已有 `sweep` 支持弯曲路径、截面渐变和扭转；本次不是缺少这类执行能力。

当前工作树的生成流程把照片微调交给 `review_design`。原实现只提交修改前、修改后的模型图，未提交原照片；其自动返修又显式传入空图列表。故照片虽在初始编辑请求中存在，到审阅与返修阶段却丢失。此处为当前源码证据，未确认首次引入的提交。

## 2. 已观测现象

- 原照片资产 `5d63f9e5-6e9e-415e-92f9-0da31f6dc92d`：中心上凹，下方有旋转支点；可见叶面沿周向弯曲、宽厚变化。单张图不能确定遮挡区域是否贯通，不能把暗部直接认定为镂空。
- 截图对应旧版本 `3a88af74-5fc2-48a1-ac6f-50bc4814b4ad`，实际八视图资产 `94737f8b-98a2-48ea-9e11-53abb847edb6`：中心上凸锥头、下方平底，三个径向椭球。叶片步骤的 path/sections 为空。
- 首次任务 `a2921b7e-c090-4f50-8a41-bb45175b366c`：照片审阅 1 次、修订 0 次；轮廓观测数 0，details 为 unverified，其余四项 pass，保留 draft。审阅文本称照片叶片“无上翘或下垂弯曲”，与实际照片存在明显冲突。
- 截图时仍在执行的后续微调任务 `01bc6723-11b2-4951-99cf-f5ce4c664ae4` 已于北京时间 12:32 完成：design_review=accepted，但 photo_fidelity.appearance_status=unverified。尺寸 59.981×59.981×24 mm 通过不能证明造型相似。

## 3. 根因与证据链

几何生产者输出椭球叶片 → Blender 按 shape 执行 → 产生与照片不同的网格。首次照片审阅虽有原图，却同时接收完整待审方案及其自述，实际返回错误匹配判断；已有观测不足检查使其保留草稿，但未提出形状纠偏。后续微调审阅和返修丢失原图，只核对文字和旧模型，最终可在照片仍未验收时通过意图审阅。

确定性代码缺陷是原图在后续链路丢失；审阅错误判断也有原始回执证明。方案自述会提供与真实图像相冲突的输入，但不能仅凭静态记录证明它是模型误判的唯一原因。

## 4. 本质

几何名称不能代替可执行形状；生成方案的自述不能作为独立外观证据；已有错误模型也不能作为照片还原的正确基准。尺寸、封闭性、类别相同与照片相似是不同的判断。

## 5. 最小修复

1. `modeling/design_review.py`：在既有审阅接口增加可选参考图输入；原图、修改前总览、修改后总览顺序明确；原图继续传给自动返修，记录 source_asset_ids/source_sha256。保持既有修订次数、局部范围校验和候选保存机制。
2. `modeling/prompts.py`、`config/modeling-prompts.yaml`：照片审阅仅接收已锁定参数，不再接收整份方案的标题、部件命名和 assumptions；要求逐项分别描述照片与模型，再比较曲率、凹凸与连接。生成提示明确刚体旋转不能制造曲率，形状必须落实到路径、截面或薄面轮廓。
3. `generation.py`：更新该分支说明，符合现在原图参与微调审阅的实际行为。

未按陀螺类别硬编码几何，未新增生成器，未降低外观门槛，未修改现有作品或历史任务状态。意图审阅仍是 design_intent，不升级为实物扫描或照片精确还原。
