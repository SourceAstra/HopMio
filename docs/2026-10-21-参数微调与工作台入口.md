# 参数微调与工作台入口

## 问题与根因

1. 出现原因：上一轮只生成 `.artifacts/design/blender-tuning.html` 设计稿，没有接入工作台，页面中没有对应入口。
2. 现象：项目中未找到 `2026-10-21_20-41.png`；实际存在 `2026-10-21_20-47.png`。该截图的中等屏幕显示“模型 / 对话 / 参数”三个独立按钮，但面板隐藏规则只在最大宽度 850px 生效。
3. 根因：入口停留在独立设计稿；851–1400px 的按钮可见性与面板切换规则错配。另一个独立契约缺口是手工参数更新仍进入允许 AI 审阅及纠错的统一生成链路。
4. 本质：设计交付没有连接真实入口，响应式控制没有对应布局状态，手工参数与自然语言规划没有独立执行契约。

## 本次改动

- 工作台加入始终可见的“参数微调”入口，已有模型且没有任务运行时可打开。
- 视图切换只出现在 850px 以内的单栏布局中；原参数检视改称“检视”，与本地微调区分。技术管线仍可打开阶段检视面板。
- 参数弹窗复用当前模型预览。桌面/平板双栏，手机单栏，页脚固定在弹窗底部。深色及 Morning Pearl 浅色均有独立主题令牌。
- 数值输入、原值提示、修改计数、恢复原值、JSON 载入与接口请求导出共用一份草稿。未提交的输入不改全局设计。
- 弹窗使用原生 dialog 提供模态、键盘焦点约束和 Esc 关闭；关闭后恢复焦点。
- 新增独立本地执行策略，复用原有 Blender 进程边界、确定性几何检查、资产清理、任务取消和版本原子提交；不调用 AI 规划、纠错或视觉审阅。
- 网页 Go 宿主、共享方法集及桌面 Electron 白名单同步开放新接口。
- 使用已保存版本作为参数基线，不将对话中尚未应用的提案混入本次请求。既有参数方案开放该方案的参数；没有参数方案的模型使用现有原网格编辑适配器，仅暴露整体缩放，保留原网格身份。

## 对外接口

与现有接口一致，通过 `/api/rpc` 发送 `{method, params}`。

读取可调参数：

```json
{
  "method": "model.parameters.describe",
  "params": {
    "schema_version": 1,
    "id": "实际作品ID",
    "base_revision_id": "当前版本ID"
  }
}
```

返回参数名、label、value、unit、locked 以及数值类型范围。范围不代替几何约束；部件尺寸、旋转、比例和最终实体仍由现有编译器及实际网格复测校验。

应用修改：

```json
{
  "method": "model.parameters.apply",
  "params": {
    "schema_version": 1,
    "id": "实际作品ID",
    "base_revision_id": "当前版本ID",
    "parameters": { "mesh_scale": 1.05 }
  }
}
```

参数键必须来自 describe。示例 mesh_scale 仅适用于描述接口确实返回该参数的作品。返回 Job，继续使用 job.get 查询、job.cancel 取消。请求不接受可执行脚本、任意新计划或用户提供的输入路径。无变化、未知参数、非有限数值、非法几何及版本冲突均拒绝。
