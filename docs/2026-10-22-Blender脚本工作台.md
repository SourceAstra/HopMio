# Blender 脚本工作台实施说明

## 1. 需求与原有限制

用户希望使用外部大模型编写 Blender Python，回到呀哈造物修改形体。原来的生成器卡片只展示固定说明，已采用按钮被禁用；内置生成器只接收六项参数，不存在粘贴代码、执行代码或管理项目脚本的接口。编辑说明文字无法改变几何。

本次新增独立脚本能力，保留参数微调入口。原参数表达式求值仍不执行 Python；用户脚本只在隔离 Blender 中运行。

## 2. 使用方法

入口：本地微调 → **Blender 脚本**。已采用的生成器卡片也提供“编辑 Blender 脚本 · 调整造型”按钮。

1. 选择“重新生成造型”或“修改当前模型”，并确认代码坐标单位。
2. 选择脚本形式。“直接运行整段脚本”适用于在 Blender Scripting 中点击运行就生成模型的代码；“调用 build(ctx, params)”适用于按本文接口编写的函数式脚本。
3. 可复制建模提示词交给外部大模型。提示词包含运行版本、入口形式、坐标单位、当前实测尺寸和已填写的目标尺寸。修改原模型时，可下载当前 GLB 一并提供给外部大模型。
4. 粘贴代码或导入 `.py`。点击“检查语法 · 读取参数”，在代码或参数控件中修改数值。错误显示 `script.py` 行号。
5. 可保存草稿；保存不执行代码。目标尺寸留空时只显示实测结果，完整填写宽、深、高时按 ±0.05 mm 复测。
6. 点击“运行并预览”。查看任务状态、运行日志与候选模型；可以停止运行。
7. 满意后点击“采用此版本”。当前版本、脚本或参数已改变时必须重新预览。

**此前提供的陀螺脚本**：选择“直接运行整段脚本”“重新生成造型”“毫米”，粘贴完整代码；可填写目标尺寸 `60 × 60 × 24 mm`。无需改成 `build` 函数。其外观是否符合照片仍需对比实际候选，源码接入不证明照片还原质量。

## 3. 脚本契约 v1

`ScriptDocument` 保存：`schema_version=1`、`source`、`entrypoint`（`script/build`）、`operation`（`replace/edit`）、`coordinate_unit`（`mm/m`）、`parameters`、可选 `expected_size_mm`。

- 整段脚本：从头到尾执行一次，收集场景中的网格。脚本须调用自己的建模函数并删除布尔刀具；场景残留的网格也会进入候选。
- 函数式脚本：执行定义后调用一次 `build(ctx, params)`，返回一个网格对象或对象列表；不应再在顶层调用该函数。
- `ctx.current`：修改模式下是由当前 STL 恢复的制造网格，已转换到所选坐标单位；重新生成模式下为 `None`。两种脚本形式均可访问它。
- `PARAMETERS`：可选顶层字面量字典，最多 48 项；名称以英文字母开头，使用英文字母、数字或下划线，最多 48 字符。值为有限数值或布尔值。
- `PARAMETER_UI`：可选顶层字面量字典，声明 `label`、`unit`、`min`、`max`、`step`。单位为 `mm/deg/ratio`；数值范围限制在 -2000～2000。整数默认值使用整数步长时，校验并保留整数类型。
- 参数控件覆盖 `PARAMETERS` 的默认值；函数入口同时接收该参数字典。源码保留原文，实际采用的参数随版本保存。
- 成品宽、深、高范围沿用项目契约 0.8～500 mm；不通过静默缩放纠正不合格尺寸。

示例声明（不是完整建模脚本）：

```python
PARAMETERS = {"diameter_mm": 60.0, "blade_count": 3}
PARAMETER_UI = {
    "diameter_mm": {"label": "直径", "unit": "mm", "min": 40, "max": 100, "step": 0.5},
    "blade_count": {"label": "叶片数量", "unit": "ratio", "min": 2, "max": 8, "step": 1},
}
```

## 4. 调用链与文件职责

| 环节 | 实现 |
| --- | --- |
| 编辑器、候选预览、错误与控件 | `ScriptEditor.tsx`、`scriptPrompt.ts`、`script-editor.css` |
| 类型、草稿与参数提取 | `script_contracts.py`；只解析 AST 字面量 |
| 项目脚本编排与采用 | `modeling/scripts.py` |
| OS 隔离接口与 Linux 实现 | `ScriptExecutor` / `BubblewrapExecutor`，位于 `script_sandbox.py` |
| Blender 中的脚本入口 | `blender/script_runner.py` |
| 几何导出与复测 | 复用 `BlenderBackend`、`building.measure`、`measurement.verify` |
| 候选与版本提交 | `start_generation(preview_only=True)`、`Projects.select_revision(promote=True)` |

公开 RPC：`model.scripts.describe / inspect / save / preview / adopt`；同步加入网页、Go 和 Electron 白名单。

草稿存储为项目级 `project_script:<id>`，绑定基础版本，删除项目时清理。生成结果保存不可变脚本文档资产，并通过 `model.script_document_id` 关联；候选可以重开查看或通过版本记录删除。采用时同时校验项目归属、父版本、候选脚本及参数，不依赖前端按钮是否禁用。

含脚本的 `.usagi` 包为 v5，包含 `script.json`；原有 v1–v4 继续支持。导入只恢复资产和引用，不执行脚本。

## 5. 执行边界与失败处理

当前实现面向 **Linux**，需要已有 Blender、Bubblewrap 和 prlimit。当前开发机能找到 `/usr/bin/bwrap`、`/usr/bin/prlimit`；这只证明工具已安装，不证明系统允许创建命名空间。Windows 与其他平台尚未实现隔离执行器，界面显示不可执行，禁止回退到宿主直接执行。

隔离进程不共享网络；只读挂载系统运行库、Blender 安装目录和任务输入，输出只允许任务目录中的普通文件。环境变量重新建立，不继承主服务密钥。临时空间和单文件、输出总量、CPU 时间、地址空间设置预算；总运行时间不超过 180 秒，取消和超时终止进程组。临时文件在任务结束后清理。

脚本输出仅传出有限顶点和三角面：宿主校验数值、索引和面数，再交给可信 Blender 导出 STL、GLB 和工程文件。不接受脚本提供的 `.blend`、清单、任意路径或复测结论。实际制造网格须通过闭合、实体、部件数及可选尺寸复测，之后才保存候选。

隔离工具存在但命名空间创建失败时，任务返回失败和运行日志；没有自动降低隔离等级。资源限制不等同于已经完成全面安全审计。

## 6. 本轮验证边界

已执行源码核对、Python AST 解析、TypeScript/TSX/JavaScript 语法解析、Go 格式检查和改动差异检查。未编译、未运行测试、未启动 Blender、未重启服务，也未做浏览器视觉与端到端验收。

人工验收建议：

- 将原陀螺脚本按第 2 节运行，检查 60 × 60 × 24 mm、候选造型、采用及回退。
- 修改 PARAMETER 控件，验证数值可清空重填、整数细分参数有效、实际几何随参数变化。
- 验证语法错误、执行异常、不闭合网格、超限尺寸、取消及超时均显示错误且保留原版本。
- 候选完成后修改代码或参数，应禁止采用；绕过前端调用采用 RPC 也应拒绝内容不一致的候选。
- 任务运行期间切换版本，应拒绝覆盖；关闭再打开面板，应能恢复草稿、运行状态和已保存候选。
- 检查桌面、平板、手机下的深浅主题、滚动和操作按钮；导出并重新导入 v5 包，确认脚本恢复且没有自动执行。

达到运行验收前，只能称为代码接入完成，不能宣称功能端到端已验证或照片造型已高保真还原。
