# 模型主参数与本地重算

## 原因、现象、根因与本质

旧参数胶囊由 IdeaPanel 遍历 parameters、匹配引用后生成，数值固定乘 1.1，再由 ChatInputDock 填入自然语言输入。这不能证明 LLM 已声明用户主参数及安全调节域。本地接口虽已绕过 AI，但原 describe 对所有参数统一给出 -2000 至 2000，缺少 UI 语义、步长及暴露边界；输入区、检视区和弹窗使用不同编辑实现。

因此这是参数契约和入口职责错配，不能通过改胶囊样式解决。当前修复将 UI 能力、几何绑定和确定性执行从自然语言修改中分离，保留原项目与历史版本。

## 当前实现

### 一份参数定义

GeometryPlan v8 扩展既有 parameters，在每个参数上声明可选 ui 元数据。字典键就是 internal_key，不再维护一份重复数值的 ui_parameters。label 继续兼容历史描述，用户只看到 ui.display_label。

- 数值：ui.control=slider，声明 min/max/step、display_label、description。初值与上限必须与 min+n*step 对齐。
- 开关：value 为真实布尔值，unit=ratio，ui.control=switch，不提供 min/max/step。
- 内部参数：不声明 ui，不出现在控件和参数 JSON 中；补丁接口拒绝修改内部参数及派生绑定。
- 新 AI 计划使用 v8 并声明 1–6 个可调主参数，范围由具体模型的可行几何关系决定，前端不按物件名称硬编码。

geometry_bindings 使用既有受限四则 AST。它可以引用主参数和其他绑定，但不能覆盖参数名、循环或超过依赖深度预算。编译时按依赖顺序求值，同时检查单位、有限数值和部件几何范围；不接受字符串公式，不使用 eval/exec。

以下仅展示契约片段，不是完整可执行模型：

```json
{
  "schema_version": 8,
  "parameters": {
    "H": {
      "value": 24, "label": "total_height_mm", "unit": "mm",
      "ui": {"display_label": "陀螺总高度", "control": "slider", "min": 16, "max": 40, "step": 1, "description": "向右拖动，作品更高"}
    },
    "blade_ratio": {
      "value": 0.35, "label": "blade_ratio", "unit": "ratio",
      "ui": {"display_label": "叶片厚度占比", "control": "slider", "min": 0.25, "max": 0.5, "step": 0.05}
    },
    "has_outer_ring": {
      "value": false, "label": "has_outer_ring", "unit": "ratio",
      "ui": {"display_label": "保留外围保护环", "control": "switch"}
    }
  },
  "geometry_bindings": {
    "blade_thickness": {"op": "multiply", "args": [{"parameter": "H"}, {"parameter": "blade_ratio"}]},
    "tip_start_z": {"parameter": "blade_thickness"},
    "tip_end_z": {"parameter": "H"}
  }
}
```

部件的 size_mm、center_mm、轮廓、截面等通过 parameter 引用上述绑定。可选保护环节点及其子工具预先声明 enabled={"parameter":"has_outer_ring"}。关闭父节点而保留依赖子节点会被拒绝；关闭后必须仍有主体。开关不能用于尺寸运算。新增未预设的拓扑仍需走自然语言规划。

相对绑定保持已声明的关系，不能保证所有参数组合都合法；最终仍须实际几何审计。内部补偿可以由有依据的派生表达式或现有算法计算，本轮没有为特定物件编造通用体素补偿算法。

### 共用编辑组件

ParameterPanel 与 useParameterDraft 由检视区和弹窗复用；“展开参数”和聊天顶部参数按钮打开同一套本地控件。材料摘要左侧保留照片/选项展开能力。已生成模型的材料栏不再提供另一套全局尺寸输入。

- slider 与数值框双向绑定，显示通俗名称、单位、影响说明。
- 默认“松手应用”：范围滑块 onPointerUp 或键盘调节释放、开关切换时提交，拖动过程中仅改草稿。数值框和 JSON 通过“立即应用参数”提交。
- 自动应用可关闭；运行期间禁用重复提交和控件，保留待应用输入。失败保留原版本。
- 每次成功应用保存新版本，视口通过既有项目/任务同步刷新；不是每个拖动事件都保存版本。
- JSON 仅编辑公开主参数，输入时实时校验并同步草稿；合法且有改动时直接应用，无需额外载入。无效 JSON 阻止提交，避免沿用旧值。可导出重算请求，主参数范围、类型及步长在服务端再次校验。

### 确定性重算接口

新增网页路径 POST /api/blender/recompute；它与 model.parameters.apply 共用服务端操作。网页使用该路径，桌面沿用 RPC。请求仅带主参数补丁及作品/来源版本身份：

```json
{
  "schema_version": 1,
  "id": "真实作品ID",
  "base_revision_id": "来源版本ID",
  "parameters": {"H": 25, "has_outer_ring": true}
}
```

按实际 describe 返回的键提交。返回异步 Job，而不是承诺同步返回 STL；通过 job.get 追踪，成功后读取新模型资产。先复用已保存计划，代入主参数并编译，再调用本地 Blender、bmesh 拓扑检查及实际网格/尺寸复测。此通路跳过 AI 规划、照片重建、视觉审阅及 AI 纠错，沿用并发、取消、超时、来源版本冲突检查、资产清理和原子保存。

成功任务记录 parameter_recompute.elapsed_ms、ai_used=false 和 topology；不声称 0.5–2 秒或 1 秒完成。当前仍有独立 Blender 进程启动、多格式导出与复测开销，性能须实测。

旧计划维持可读，未补齐 UI 契约时不会猜测标签与局部安全范围，也不会自动送模；本地编辑采用原网格适配器，只提供整体等比缩放。原参数计划留在历史版本，不会被原地改写。
