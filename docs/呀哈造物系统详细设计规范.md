## 1. 项目愿景与产品世界观

### 1.1 产品定位与共创愿景
呀哈造物（YaHa Craft）是一款面向 12 岁少年及其家庭共同创作的 3D 打印创造力工作台。产品以“乌萨奇小屋造物之旅”为核心世界观，打通“收集灵感 → 整理材料 → 确认想法 → 本地造物 → 模型体检 → 打印准备 → 实体制造 → 展厅入驻”全生命周期链路。

- **孩子的第一个软件作品**：孩子不仅是使用者，更是软件的共同设计者。孩子可以通过大白话、涂鸦或照片表达灵感，理解尺寸、公差与物理空间，并能在“小屋工坊”中参与修改样式、模板与代码。
- **真机制造导向**：直面消费级 FDM 3D 打印机（以拓竹 Bambu Lab A1 mini 单色版 180×180×180 mm 为首个验证基线），拒绝虚假的演示贴图与浮夸的概念渲染，确保输出的模型 100% 具备物理水密性与制造可行性。

### 1.2 乌萨奇主题硬性约束
本项目统一使用正版授权视觉资产，贯穿主页、导航、小屋空间、陪伴向导与展厅：
1. **角色特征**：统一采用奶油黄色身体、大头短身、细长粉色内耳、亮黑圆眼、弯眉、开心的 $\omega$ 形嘴和脸颊三条刻线。单色打印模型必须通过物理轮廓与表面雕刻表情保持鲜明辨识度。
2. **严禁替代**：绝对严禁使用通用小兔、卡通兔子 emoji、无特征几何体或第三方兔子吉祥物替代乌萨奇；严禁仅修改文案名称而使用通用模型。
3. **视觉与素材资产归一**：
   - 核心插画与形象入口：[`public/art/usagi/`](file:///home/he/HopMio/public/art/usagi) 与 [`dist/art/usagi/`](file:///home/he/HopMio/dist/art/usagi)（复用 `companion.png` 与 `cottage.png`）。
   - 默认角色参数化模型：[`backend/yaha/geometry/usagi.py`](file:///home/he/HopMio/backend/yaha/geometry/usagi.py)，封装为受信任的 Blender 角色模板。

### 2.1 架构分层职责
1. **呈现层 (Web Frontend - `src/`)**：
   - 基于 TypeScript + React 18 + Three.js 硬件加速构建；
   - 采用标准 CSS Tokens（`src/styles/tokens.css`）实现晨曦暖白创客风格；
   - 经由构建工具输出至 `dist/`，由 Go 宿主服务直接托管分发。
2. **宿主中枢 (Go Core - `cmd/server/main.go`, `core-go/`)**：
   - 系统宿主主入口，支持编译为单二进制 `bin/hopmio`；
   - **进程守护者 (Supervisor)**：自适应检测独立计算内核（`bin/hopmio-engine` / `bin/yaha-engine`），或平滑回退至 `.venv/bin/python`，以 `-u -m yaha` 启动 Python 引擎子进程；
   - **安全 IPC 通信**：基于标准输入输出（`stdin/stdout`）的行驱动异步 JSON-RPC 2.0 双工通信管道，免除本地端口被占用或被防火墙拦截的安全风险；
   - **API 网关与 SSE**：托管静态页面，提供 `/api/rpc` 白名单接口转发与 `/api/events` 长任务流式事件推送。
3. **计算与几何内核 (Python Engine - `backend/yaha/`)**：
   - 完整的领域计算命名空间 `backend/yaha/`，通过 `PYTHONPATH=backend` 模块化运行；
   - 包含 AI 多模态理解、参数规划、Blender 驱动、摄影测量重构、拓竹切片及 SQLite 状态存储。

## 4. AI 智能大脑与参数化规划链路

大语言模型（GLM-4 / DeepSeek-V3 / Qwen-2.5-Coder）在系统中**严格定位为“参数规划器与视觉解构器”，严禁直接向几何引擎投喂未经校验的可执行脚本**。

```
[自然语言 / 多视角图像]
       │
       ▼
[多模态理解器 (understanding.py)] ── 提取主体轮廓与尺寸意图
       │
       ▼
[提示词蓝图规划 (planner.py)] ── 产出强类型结构化草案 (JSON Mode)
       │
       ▼
[契约与约束校验 (contracts.py)] ── AST 白名单数学表达式与尺寸约束求值
       │
       ▼
[Blender 几何引擎 (driver.py)] ── 受信任的参数化原语求值与实体布尔运算
       │
       ▼
[物理尺度复测 (validation.py)] ── 导出的制造网格尺寸核验通过后原子提交
```

### 4.1 提示词蓝图规划契约 (`GeometryPlan/v4`)
系统核心几何规划采用 [`backend/yaha/modeling/contracts.py`](file:///home/he/HopMio/backend/yaha/modeling/contracts.py) 定义的 `GeometryPlan/v4` 强类型契约。每个部件显式声明坐标原点语义（`bounds_center` 或 `local_origin`）：

```json
{
  "schema_version": 4,
  "title": "圆笔筒",
  "source_prompt": "做个圆笔筒，高 100mm，外径 80mm，壁厚 3mm，底厚 4mm",
  "parameters": {
    "height_mm": {"value": 100.0, "label": "笔筒高度", "unit": "mm", "locked": false},
```

### 4.2 语法沙箱与自然语言增量微调
- **表达式安全求值**：参数计算仅允许白名单运算符（`add`, `subtract`, `multiply`, `divide`），禁止任何 `eval`、`exec` 与外部系统调用。
- **增量调整协议 (`ModelAdjustment/v1`)**：当用户在造物桌输入“耳朵大一点、鼻子向上弯”时，系统产生绑定当前版本的指令与可选标记坐标点（`location_point`），基于现有几何方案进行局部补丁（Patching），确保未被要求变动的尺寸绝对固定。

### 4.3 外部 Blender 脚本工作台（2026-10-22）

微调面板提供“参数调整 / Blender 脚本”切换。用户从外部大模型获取脚本后，可粘贴、导入、保存草稿、运行预览并采用候选版本。支持整段直接运行和 `build(ctx, params)` 两种明确入口；生成器说明文字仍是介绍，卡片新增脚本编辑入口。

- `ScriptDocument/v1` 保存源代码、入口类型、重新生成/修改原网格模式、坐标单位、参数及可选目标尺寸。`PARAMETERS` 和 `PARAMETER_UI` 仅以 AST 字面量提取，主服务不执行脚本。
- `ScriptExecutor` 隔离执行接口目前实现 Linux Bubblewrap + prlimit。只读输入为当前制造网格，输出仅接受有限顶点和三角面，再走现有可信 Blender 导出及实际网格复测。未配置隔离执行器的平台不可运行，禁止回退到宿主裸执行。
- 预览保存候选，不激活当前版本；采用时同时核对项目、基础版本、候选、脚本和参数。失败、取消或版本冲突保留当前模型。候选沿用历史版本删除入口，临时执行目录自动清理。
- 已采用脚本随模型版本保存；含脚本的作品包使用 v5，导入仅恢复数据，不执行附带代码。原有 v1–v4 作品包继续支持。
- 桌面、平板、手机复用深色与 Morning Pearl 主题。实施与人工验收说明见 `docs/2026-10-22-Blender脚本工作台.md`。源码与静态检查不代表隔离运行或端到端已验收。

## 5. A+B 逆向工程制造管线 (Reverse Engineering Pipeline)

针对现实世界物理实体或复杂手办的 3D 数字化制造，系统设计并落地了首创的 **A+B 深度融合逆向制造管线**：

```
[客户端 Web 上传 24~60 张照片 + 目标高度]
                    │
                    ▼
[Go 宿主中枢 (core-go/api/)] ── 派发任务至 Python 引擎
                    │
                    ▼
[阶段 A：摄影测量重构 (backend/yaha/reconstruction/)]
  ├─ 1. 特征提取 (DSP-SIFT) & SfM 相机位姿求解 (PyColmap)
  ├─ 2. 稠密点云插值重建 (OpenMVS)
  └─ 3. 泊松表面重建，产出高密裸网格 raw_mesh.ply
                    │
                    ▼
[阶段 B：Blender 工业级自动化精修 (backend/yaha/blender/)]
  ├─ 1. 几何微破洞拉普拉斯流形缝合与去噪
  ├─ 2. 特征保持微光顺 (Laplacian Smoothing)
  ├─ 3. 物理尺寸毫米级绝对定标 (等比缩放或实物标尺校准)
  └─ 4. 打印接触面水平切削 (Bed-Leveling Cut) 与防倒底座生成
                    │
                    ▼
[阶段 C：制造校验与切片 (backend/yaha/slicing/)]
  ├─ 1. 水密流形强检 (2-Manifold、壁厚 ≥ 0.8mm、正法线)
  └─ 2. Bambu Studio CLI 展开 A1 mini 官方预设，输出 .gcode.3mf
                    │
                    ▼
[原子提交新版本] ── 资产落盘至 .state/assets/，SQLite 版本指针更新，SSE 通知前端视口刷新
```

### 5.1 阶段 A（真实之魂 · 表面重构）
1. **多视角受控采样**：支持 12~96 张重叠照片输入（推荐 24~60 张环绕仰俯角）。
2. **自适应主体分割**：通过 GrabCut / OpenCV 前景深度估计剔除杂乱桌面背景，生成精准 Alpha Mask。
3. **相机求解与特征匹配**：PyColmap 执行仿射不变性 DSP-SIFT 特征提取与极线几何配准，重建稀疏 3D 特征点云与相机内参/外参。
4. **表面泊松重构**：OpenMVS 执行高密度点云插值与泊松曲面网格化，保存原始未破损曲面网格。

### 5.2 阶段 B（制造之刃 · Blender 自动化精修）
直接重构的网格存在非流形边、浮动自交碎面、缺失绝对尺度与无平整底面。Blender 后台无头进程执行严格的工业精修：
1. **孤立碎片剔除与拓扑修复**：移除体积占比小于 2% 的浮动孤岛，执行非流形边焊接。
2. **拉普拉斯微光顺**：消除点云量化噪声，同时保留面部刻线与边缘特征。
3. **毫米级尺度严格定标**：
   - 用户指定高度模式：$Z_{\text{target}} = H_{\text{mm}}$，执行严格等比坐标缩放；
   - 标尺模式：根据两点间已知实际物理间距（如硬币或标尺）换算物理世界变换矩阵。严禁非等比扭曲三轴。
4. **打印接触面水平切削 (Bed-Leveling Cut)**：
   - 寻找物体质心与稳定朝向；
   - 在底部 $Z = Z_{\min} + \Delta h$（通常为 0.5~1.0 mm）应用水平布尔剖切，构造绝对平滑、零翘曲的 FDM 打印接触底面；
   - 可选自动生成可拆卸式椭圆稳定防倒底座。

### 5.3 阶段 C（制造门禁与 Bambu Studio 切片）
1. **水密流形强体验收门禁**：
   - 必须满足 2-流形几何（2-Manifold）；
   - 法线方向必须向外一致；
   - 自交面数量必须为 0；
   - 最小实体壁厚不得小于 0.8 mm（两倍喷嘴直径）。
2. **Bambu Studio CLI 切片交互**：
   - 展开拓竹官方 A1 mini 预设配置（0.4mm 喷嘴、0.20mm 标准层高、PLA 官方线材）；
   - CLI 实际生成 `.gcode.3mf` 生产制造文件，提取打印层数、耗材总克数、预计时长（分/秒）与树状支撑分布体积；
   - 绝不使用前端粗糙估算冒充真实切片数据。

## 6. 核心数据契约与不可变版本控制 (SSOT)

系统采用完全受控的数据版本化管理，杜绝状态冲突与悬空脏数据。所有项目状态统一落盘于 `.state/`。

### 6.1 核心数据实体契约关系

```
[Project (项目主数据)]
   │
   └── contains ──> [Revision (不可变历史版本)]
                        │
                        ├─ defines ──> [DesignSpec/v5 (需求规格)]
                        ├─ executes ─> [GeometryPlan/v4 或 ReconstructionPlan/v1]
                        ├─ produces ─> [Artifacts (.blend, .stl, .3mf, .glb)]
                        └─ sliced_by > [SliceResult (.gcode.3mf, 耗材, 时长, 层数)]
```

### 6.2 版本不可变性与两阶段原子提交
1. **暂存区隔离 (Staging Isolation)**：
   建模与重构的所有中间产物（网格、日志、临时场景）均写入 `.state/staging/{task_id}/`。
2. **两阶段原子提交 (Two-Phase Commit)**：
   - **Phase 1: 几何与尺寸复测**。重新回读导出的 STL/3MF，验证长宽高公差（$\le 0.05\text{ mm}$）与水密封闭性；
   - **Phase 2: 资产迁移与元数据落盘**。将暂存文件迁移至 `.state/assets/{hash}`，在 SQLite 中将活动版本指针原子更新为新 `Revision`。
3. **回退与分支保护**：
   任何失败的任务不会污染当前活跃版本；用户随时可以回退至历史任意 `Revision` 重新分支设计。

## 8. 进程管理、资源安全与平台部署

### 8.1 进程池守护与健康探针 (Go Daemon)
1. **生命周期监管**：Go 宿主启动时自动检测并拉起 Python 引擎，建立 `stdin/stdout` 标准输入输出的双工 JSON-RPC 通信管道；
2. **崩溃自愈**：当计算引擎因极端异常（如内存越界或 Python 崩溃）退出时，守护进程记录事故快照，在 500ms 内自动重启计算内核并恢复任务上下文；
3. **任务超时与进程树绞杀**：每个建模任务分配独立进程组（Linux `setpgid` / Windows `JobObject`），当任务超时（默认 180s）或用户取消时，宿主保证 100% 斩断所有 Blender 与 Python 子进程，严禁内存孤儿泄漏。

### 8.2 平台运行标准与一键分发
1. **统一启动规范**：
   - Linux: `./deploy.sh` 编译并后台拉起宿主服务，访问 `http://127.0.0.1:5173/`；
   - Windows: 双击 `启动YaHa.cmd`，自动拉起核心服务与浏览器视口；
   - 依赖安装: Linux 执行 `./setup.sh`，Windows 执行 `安装建模工具.cmd`。
2. **生产环境资产收敛**：
   - 前端构建产物统一收敛于 `dist/`，由 Go 宿主服务托管；
   - 运行时持久化数据统一收敛于 `.state/`，临时构建产物收敛于 `.artifacts/`。
